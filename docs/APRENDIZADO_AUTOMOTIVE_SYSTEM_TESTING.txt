AULA 1 — SISTEMA SOB TESTE, AMBIENTE E PRIMEIRA EVIDÊNCIA
===============================================================================

Objetivo
-------
Entender o que estamos construindo, o que será testado e por que o emulador não
equivale completamente a um veículo.

1. Os dois produtos deste repositório
-------------------------------------

CarSystemUI de plataforma:

- código AOSP real;
- componente privilegiado do Android Automotive OS;
- compilado por Soong dentro de uma árvore AOSP;
- depende de CarService, VHAL, assinatura e permissões de sistema;
- é o sistema real que desejamos estudar.

Showcase:

- aplicativo Android comum e executável pelo botão Run;
- criado para aprendizado e demonstração visual;
- simula estados automotivos;
- não substitui nem afirma validar o CarSystemUI real;
- prepara limites para integração futura com ATEP e simulador elétrico.

2. SUT — System Under Test
--------------------------

SUT significa “sistema sob teste”.

Na primeira etapa:

  SUT = aplicativo CarSystemUI Showcase.

Em etapas futuras:

  SUT = CarSystemUI real executando em uma imagem AAOS.

Essa identificação precisa estar presente em qualquer relatório. Um teste que
passou no showcase não prova que o CarSystemUI de plataforma também passará.

3. Ambiente de teste
--------------------

O ambiente inclui tudo que pode influenciar o resultado:

- código e versão do build;
- sistema operacional Android;
- API level;
- tipo de emulador ou hardware;
- resolução e densidade;
- usuário ativo;
- idioma e modo noturno;
- dados simulados;
- conectividade;
- overlays;
- ferramentas utilizadas.

Ambiente encontrado em 29/07/2026:

- host Linux x86_64;
- Java 17;
- Android SDK configurado;
- imagem Android Automotive API 33 instalada;
- nenhum AVD criado;
- KVM indisponível;
- nenhum dispositivo conectado.

Conclusão correta:
O ambiente ainda não está pronto para executar a interface.

Conclusão incorreta:
“O aplicativo não funciona.”

Ainda não executamos o aplicativo; portanto, não existe evidência para fazer essa
afirmação.

4. Teste manual versus automatizado
-----------------------------------

Teste manual:
Uma pessoa prepara o cenário, executa as ações, observa e registra o resultado.

Teste automatizado:
Código ou ferramenta executa ações e verificações de forma repetível.

Nesta etapa faremos teste manual. Nenhuma automação será criada antes da aula
específica, do desenho do teste e da confirmação explícita do aprendiz.

5. Primeiro objetivo de teste
-----------------------------

Objetivo:
Confirmar que a fundação do showcase compila, instala e apresenta a tela inicial
em um emulador Android Automotive.

Riscos cobertos:

- configuração Gradle inválida;
- incompatibilidade entre Java, Gradle, plugin Android e SDK;
- manifest incapaz de iniciar a Activity;
- recurso ou classe ausente;
- APK não instalável;
- crash imediato ao abrir.

Riscos ainda não cobertos:

- comportamento real de CarSystemUI;
- sinais CAN;
- VHAL e CarService reais;
- veículo elétrico;
- múltiplos displays reais;
- performance representativa;
- segurança automotiva;
- integração com ATEP.

6. Oráculo de teste
-------------------

Oráculo é a fonte usada para decidir o resultado esperado.

Para o primeiro smoke test, o esperado será definido pelo requisito simples:

  “Ao iniciar o showcase, deve ser apresentada uma tela identificada como
   CarSystemUI Showcase, sem encerramento inesperado.”

7. Evidências planejadas
------------------------

- saída do build Gradle;
- nome e fingerprint do emulador;
- instalação concluída;
- captura da tela inicial;
- ausência de crash imediato no logcat;
- ficha do CT-001 preenchida.

8. Estados possíveis de uma execução
------------------------------------

APROVADO:
Todos os resultados esperados do caso foram observados.

REPROVADO:
O sistema foi executado, mas algum resultado esperado não ocorreu.

BLOQUEADO:
Não foi possível executar por causa externa ao comportamento avaliado.

NÃO EXECUTADO:
O caso ainda não foi iniciado.

Situação atual:
BLOQUEADO para execução visual, pois não há AVD e o KVM está indisponível.
